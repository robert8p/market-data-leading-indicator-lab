# SEC temporal evidence, observed 24 October 2026

The SEC’s own [Webmaster FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions), last reviewed 23 August 2024 and retrieved through web search 24 October 2026, distinguishes EDGAR acceptance from content availability. The section on filing lag states a typical 1–3 minute delay but expressly declines to guarantee or predict it. The timestamp section says no SEC timestamp identifies when filing content first becomes available on sec.gov. The header acceptance time therefore cannot be copied into source_published_at or historical_received_at.

Acceptance is still useful F01 metadata when tied to the exact accession and retained header/index bytes. Preserve the original source text and clock label. The FAQ describes the time label as EST; a daylight-saving conversion needs an explicit accepted clock convention and should not erase that source wording. The retained CRD index displays 2026-08-03 16:24:33, after the regular 16:00 close even before resolving the UTC representation; it is not pre-close publication evidence.

For F04/F05, actual issuer announcement evidence must establish the earliest supported public event separately. Licensed historical collection/receipt logs may establish a vendor’s observation time, but they do not become this mission’s original receipt. Reconstructed availability and strict original receipt qualification must remain separate. A fixed 1-minute, 3-minute or arbitrary conservative delay is not proof of actual publication.

This is a primary-source feasibility finding, not a new blanket hold: all source acquisition, exact extraction, identities and numerical derivations can proceed. No current data-source API calls or purchases were made for this documentation check. No production field was changed.
